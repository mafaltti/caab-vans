# Implementation Plan: OSRM Route-Based ETA

**Branch**: `037-osrm-eta-baseline` | **Date**: 2026-03-04 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `specs/037-osrm-eta-baseline/spec.md`

## Summary

Replace the haversine × 1.3 ETA calculation with a three-layer system: (1) OSRM road distance + GPS speed, (2) time-of-day correction factors with seeded defaults, and (3) a nightly refinement script that auto-updates factors from actual trip data. The system ships fully functional from day one with hardcoded rush hour defaults, and progressively improves as data accumulates.

## Technical Context

**Language/Version**: TypeScript 5.x (Next.js App Router)
**Primary Dependencies**: Next.js, Luxon, Zod, OSRM (self-hosted, existing)
**Storage**: PostgreSQL (Supabase, existing) + JSON file (new, for correction factors)
**Testing**: Vitest

**Project Type**: Web service (BFF layer)
**Performance Goals**: <25ms p95 added latency from OSRM `/route` call
**Constraints**: 100ms OSRM timeout, graceful fallback to haversine, zero-config backward compatibility
**Scale/Scope**: 3-5 vans, ~10 trips/day, 5-15 stops per route

## Implementation Details

### Layer 1: OSRM Road Distance

**File: `src/lib/tracking/osrm.ts`** — Add `osrmRoute()`:

```typescript
export interface OsrmRouteResult {
  distanceMeters: number;
  durationSeconds: number;
}

export async function osrmRoute(
  fromLat: number, fromLng: number,
  toLat: number, toLng: number,
  osrmBaseUrl: string,
): Promise<OsrmRouteResult | null> {
  const url = `${osrmBaseUrl}/route/v1/driving/${fromLng},${fromLat};${toLng},${toLat}?overview=false&annotations=false`;
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), 100);
  try {
    const res = await fetch(url, { signal: controller.signal });
    clearTimeout(timer);
    if (!res.ok) return null;
    const data = await res.json();
    if (data.code !== "Ok" || !data.routes?.[0]) return null;
    return {
      distanceMeters: data.routes[0].distance,
      durationSeconds: data.routes[0].duration,
    };
  } catch {
    clearTimeout(timer);
    return null;
  }
}
```

**File: `src/lib/tracking/eta.ts`** — Modified GPS branch:

```typescript
// Before (sync):
const distanceMeters = haversineDistanceMeters(...);
const travelMinutes = (distanceMeters * ROAD_FACTOR) / vanPosition.speedMps / 60;

// After (async, OSRM-first):
let distanceMeters: number;
let etaSource: "gps" | "gps_osrm" = "gps";

const osrmResult = osrmBaseUrl
  ? await osrmRoute(vanPosition.lat, vanPosition.lng, stopLat, stopLng, osrmBaseUrl)
  : null;

if (osrmResult) {
  distanceMeters = osrmResult.distanceMeters;
  etaSource = "gps_osrm";
} else {
  distanceMeters = haversineDistanceMeters(...) * ROAD_FACTOR;
}

const baseTravelMinutes = distanceMeters / vanPosition.speedMps / 60;
const factor = getTimeFactor(now.hour, now.weekday, routeId, recentRuns);
const travelMinutes = baseTravelMinutes * factor;
```

### Layer 2: Time-of-Day Correction Factors

**File: `src/lib/tracking/time-factors.ts`** (new):

Key functions:
- `getTimeFactor(hour, dayOfWeek, routeId?, recentRuns?)` → number
- `loadFactors()` → reads `data/time-factors.json` or returns hardcoded defaults
- `computeRecentFactor(recentRuns)` → number (median of actual/predicted ratios)

Blend formula: `factor = recentRuns.length > 0 ? 0.7 * historical + 0.3 * recent : historical`

Hardcoded defaults (seeded for any city):
- Weekday 7-8 AM: 1.35-1.40 (morning rush)
- Weekday 5-6 PM: 1.30-1.35 (evening rush)
- Off-peak: 1.0
- Weekend: 1.0-1.10

### Layer 3: Nightly Refinement Script

**File: `scripts/compute-time-factors.ts`** (new):

Pipeline:
1. Query completed route_run_stops with passed_at from last 30 days
2. For each stop-to-stop segment: compute actual travel time (from passed_at timestamps)
3. For each segment: compute what the system would have predicted (OSRM distance / avg GPS speed)
4. Compute correction_factor = actual / predicted for each observation
5. Aggregate by (dayType, hour) → median factor (global)
6. Check per-route variance; if >15% for a bucket, generate route-level override
7. Write `data/time-factors.json`

### Fallback Chain

```
1. OSRM road distance / GPS speed × time factor  → etaSource: "gps_osrm"
   ↓ (OSRM timeout/down/no route)
2. Haversine × 1.3 / GPS speed × time factor     → etaSource: "gps"
   ↓ (no GPS, stale position, van stopped)
3. Schedule time + delay offset                   → etaSource: "schedule"
```

Time factor applies to both GPS paths (road and haversine). Schedule fallback does not use time factor (it already incorporates observed delay).
