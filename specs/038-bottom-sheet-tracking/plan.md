# Implementation Plan: Bottom Sheet Tracking UI

**Branch**: `038-bottom-sheet-tracking` | **Date**: 2026-03-04 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/038-bottom-sheet-tracking/spec.md`

## Summary

Replace the card-based route detail layout with a fullscreen map + draggable bottom sheet when a route is actively running with GPS data. The sheet has three snap points (peek/half/full) showing progressively more schedule information. Non-running routes keep the existing card layout. Uses Vaul (shadcn Drawer) for gesture handling, reuses existing VanTrackingMap and ScheduleTimeline components.

## Technical Context

**Language/Version**: TypeScript 5.x, React 19, Next.js 15 (App Router)
**Primary Dependencies**: Vaul (new, ~5 KB via `shadcn add drawer`), MapLibre GL, react-map-gl, Motion, TanStack Query, Lucide React
**Storage**: N/A (no database changes — purely frontend)
**Testing**: Vitest (unit), manual testing on iOS Safari + Android Chrome (gesture/layout verification)
**Target Platform**: Mobile web (iOS Safari 15+, Android Chrome), responsive
**Project Type**: Web application (Next.js)
**Performance Goals**: Sheet transitions < 400ms, page load to peek visible < 1s, bundle addition < 10 KB gzip
**Constraints**: Must not regress existing card layout for non-running routes; must handle iOS Safari gesture quirks (rubber-banding, viewport bounce)
**Scale/Scope**: Single page change (route detail), 3 new components, 2 modified components
