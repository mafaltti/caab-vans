# Implementation Plan: Tracker Boot Restart

**Branch**: `042-tracker-boot-restart` | **Date**: 2026-03-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/042-tracker-boot-restart/spec.md`

## Summary

Add automatic GPS tracking restart after device reboot, battery death, OS update, or app update on Android. Implemented via an Expo config plugin that injects a native BroadcastReceiver (Direct Boot-aware) and a device-protected storage module. The receiver checks a persisted flag and launches the app to trigger the existing auto-resume logic — no tracking code duplication.

## Technical Context

**Language/Version**: TypeScript 5.x (JS layer) + Kotlin (native Android, injected by config plugin)
**Primary Dependencies**: expo-location ~55.1.2, expo-task-manager ~55.0.9, @expo/config-plugins (build-time)
**Storage**: Device-protected SharedPreferences (new, for boot flag) + AsyncStorage (existing) + SecureStore (existing)
**Testing**: Manual device testing (reboot scenarios); unit tests for JS wrapper logic via vitest
**Target Platform**: Android 8.0+ (API 26+), with Direct Boot on Android 7.0+ (API 24+)
**Project Type**: Mobile app (Expo/React Native tracker)
**Performance Goals**: Tracking resumes within 90 seconds of boot completion
**Constraints**: Must work before device unlock (Direct Boot); must not duplicate JS tracking logic in native code
**Scale/Scope**: Single tracker app, ~5 new files, ~3 modified files
