# Local Dev Setup Quickstart

Based on the spec's quickstart, you need the local Supabase stack running and seed data. Here's the step-by-step:

## 1. Start Supabase (if not already running)

```bash
cd infra/supabase
docker compose up -d
```

## 2. Run Migrations and Seed

```bash
npm run db:migrate
npm run db:seed
```

## 3. Set Up Your `.env.local`

Copy the example and fill in your local Supabase keys:

```bash
cp .env.local.example .env.local
```

Edit `.env.local` with the keys from your Supabase instance (default local values are usually in `infra/supabase/.env.example`).

## 4. Start the Dev Server

```bash
npm run dev
```

## 5. What to Test

- **Home page** ([http://localhost:3000](http://localhost:3000)) — should show route list (or "Nenhuma rota configurada" if empty)
- **Route detail** ([http://localhost:3000/routes/\<uuid\>](http://localhost:3000/routes/<uuid>)) — schedule, next stop, location link CTA
- **API directly:**

```bash
curl http://localhost:3000/api/routes
curl http://localhost:3000/api/routes/<route-uuid>
```

## 6. If You Need Test Data

Since there's no admin UI yet (Phase 4+), you can insert routes/vans/schedule entries directly via Supabase Studio at [http://localhost:54323](http://localhost:54323), or via SQL:

```sql
-- Create a van
INSERT INTO vans (name, location_url, location_updated_at, ingestion_token)
VALUES ('Van 01', 'https://maps.app.goo.gl/example', now(), 'test-token-1');

-- Create a route linked to that van
INSERT INTO routes (name, van_id)
VALUES ('Rota Centro', (SELECT id FROM vans WHERE name = 'Van 01'));

-- Add schedule entries
INSERT INTO schedule_entries (route_id, stop_name, time) VALUES
  ((SELECT id FROM routes WHERE name = 'Rota Centro'), 'Ponto Inicial', '07:00'),
  ((SELECT id FROM routes WHERE name = 'Rota Centro'), 'Ponto Central', '07:30'),
  ((SELECT id FROM routes WHERE name = 'Rota Centro'), 'Ponto Final', '08:00');
```

Run this in Studio's SQL editor or via `psql` using your `DATABASE_URL`.
